## Trusted connector interface

`PublicationContext` is a frozen authority. The trusted connector independently pins repository/PR/workflow/run origin; full head/base-tip/comparison-base and object format; artifact and admitted reviewer SHA-256 identities; expected tool identifier, trusted policy/config/profile, the versioned canonical full-scope digest, exact report-byte SHA-256, and immutable `PublicationRange` diff locations. Reviewer/artifact bytes and the report tool identifier are different identities. Report fields, report envelopes and environment strings cannot construct publication authority.

`publish_report(..., expected_context=authority, raw_report_bytes=downloaded_bytes, current_authority=connector_callback)` strict-decodes those original bytes and recomputes their SHA-256. `report_dict` must match the decoded record; reserialization cannot substitute for the downloaded bytes. The callback receives fresh PR data and must independently refresh origin, trusted contract, artifact and permitted-diff authority. Missing authority/callback/raw bytes refuses publication. There is no report-derived expected-context fallback. The CLI's existing beta admission remains disabled; extended developer invocation has no trusted connector adapter and therefore fails closed.

Before **every** actual POST or PATCH, including retries, the transport invokes the mandatory pre-write guard. The guard reacquires current PR data and reruns the connector callback and full gate. Missing/stale current metadata or drift stops the next write. The callback is trusted connector code, not code or configuration loaded from a reviewed repository. The upstream connector remains responsible for independently authenticating platform origin and obtaining the current trusted manifest; a caller-supplied report envelope is never that connector.
