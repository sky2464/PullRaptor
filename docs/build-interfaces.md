# Coordinator decisions for the build queue

Date: 2026-10-03. Code/trusted base: `28b623ab1bb238ef11fbf07b29c1c773522a4a42`. These decisions make the existing child tasks implementable. They do not accept a product, select a live tenant/provider, authorize target execution or activate an endpoint. The [build board](build-task-board.md) and [task registry](build-tasks.json) identify owners, dependencies, files and checks. Child specifications retain their acceptance criteria and resource limits; these interface amendments take precedence over an older conflicting signature.

## E02: immutable capture and publisher integration

Use `capture_local` as the sole local-capture entry point for CLI and MCP. Remove the stale MCP import of `freeze_working_tree`; verify both consumers against identical staged/worktree inputs. Expose `include_untracked=False` explicitly on both surfaces, with an opt-in boolean, rather than silently widening scope. Preserve commit-review acquisition.

Capture returns an owned lifetime handle for temporary object storage: review reads through that handle until final report materialization, then cleanup occurs in `finally`. No sealed snapshot may reference an already deleted object store. Traverse admitted paths through no-follow descriptors for every ancestor and final component; unsupported platforms refuse the affected capture rather than silently following links. Verify file identities/content and index/ref identities immediately before sealing; concurrent change yields `capture_race`, incomplete discovery and explicit gaps. The capture process must not write the customer's index/refs/worktree or invoke filters/hooks. Add object-store lifetime, ancestor-symlink and race tests alongside the existing child cases.

Extend the publisher with an independently derived `PublicationEnvelope` (schema 1): platform/repository/PR, workflow/run, artifact-byte digest, admitted reviewer artifact digest, exact object format/full head/base-tip/comparison-base, trusted policy/config digests, profile and canonical full expected-scope digest. Scope digest covers every `ScopeEntry` field, not just inventory path names. Git SHA-1/SHA-256 format is obtained from the admitted repository; no prefix comparison. An envelope in an uploaded report is untrusted: compare it with platform origin metadata, downloaded bytes and a trusted-base coordinator manifest.

Before any write, strict-decode the report, recompute canonical contract/scope digests, bind `Report.contract` to the independently pinned manifest, and validate unique expected receipt keys, each receipt's contract/capability/status, inventory and inline coordinates. Missing/foreign/duplicate receipts cannot make coverage complete. `limit_failure` has no inline comments. Partial full reports may expose only individually validated findings with visible coverage; invalid bindings deny all writes. Acquire current platform context again immediately before each write. Platform paths and side/line coordinates come from the current diff; a path in inventory alone cannot validate a deleted-side location.

The connector derives the authenticated publisher's platform actor/application identity from its own authenticated channel; a marker or a hardcoded owner string cannot prove ownership. Use a trusted connector interface with `current_context`, `list_owned_observations` and `write_observation` methods; pure tests use inert implementations. Reconcile by repository/PR/rule-version/obligation identity and witness, preserving old/new observation IDs. Distinguish out-of-cap findings from outdated findings. Dismissed unchanged witnesses stay suppressed but remain evidence; changed witnesses become visible, preserving the prior dismissal history. A lost write response requires reading/reconciliation before retry; an ambiguous match stops writes with an explicit receipt. Cap 10 inline comments while preserving the full report. No token enters the analyzer or report artifact.

## E04: bounded worker stdin

E04-D0 extends `run_bounded(..., input_bytes: bytes | None = None, max_input_bytes: int = 0)`. Existing Git calls retain `None`/DEVNULL. A non-null request requires an explicit positive cap; reject over-cap input before launch. Use one pipe for a single strict schema-versioned JSON request, close stdin after the last byte, and concurrently drain bounded stdout/stderr using nonblocking I/O. Input writes, output reads and tree cleanup share the existing absolute review deadline; do not restart a timeout per phase. Handle partial writes, EPIPE, early exit, cancellation and output overflow without hanging or claiming completion.

Worker cwd, executable/digest, grammar/digest and environment come only from the trusted registry; no repository scripts, inherited secrets or shared caches. Tests may launch explicitly assigned inert development fixtures; actual parser execution requires its separate runtime/license/control admission. The worker returns one strict result; the coordinator derives expected scope independently and rejects extra/omitted/duplicate receipts. This is process bounding, not proof of a hostile OS isolation boundary.

## E05: owned statement IR and Python lowering

Current `BoundFacts` contains lexical facts, not the ordered statements needed by a CFG. E05-D1 creates `python_ir.py` and `python_lowering.py`; amend Task 1 to consume `BoundStatementIR`, not reconstruct statements from symbols/imports.

Frozen `StatementIR` schema 1 contains blob digest, producer/schema/runtime/model identities, function-local ordered node IDs, operation records, relative UTF-8 spans, explicit successor kinds and boundary records. It contains no repository path, tenant, credentials or occurrence identity. `BoundStatementIR` adds a coordinator-validated occurrence/path and review-contract identity after validated fresh extraction or admitted private-cache reuse. Cache keys include bytes and all parser/lowering/config identities. The lowerer accepts bytes and a pinned Python AST runtime, never a live imported target module.

Initial operations: local assignment, literal/name/value-preserving expressions, resolved call, branch, while/for loop, return/raise, and explicit exception boundary. Initial supported control flow is straight-line code, `if`, bounded `while`/`for` with break/continue/else, and return/raise. `try`/`with`, generators/async, comprehensions, dynamic dispatch, nested-function effects and unsupported syntax emit explicit incomplete boundaries; unknown effects conservatively retain hazards. Do not invent exception successors as complete. E05-D1 records parameter, assignment, import and scope bindings to resolve unshadowed built-in `input`; existing lexical facts do not establish that identity. Reuse only validated E01 qualified `subprocess` identities. Parameter-shadowed, reassigned, imported and ambiguous `input` cannot seed PYSEC001. Ambiguous call resolution is unknown. The Task 1 signature becomes `build_cfg(ir: BoundStatementIR, model: SecurityModel, *, limits: Limits, deadline: Deadline) -> ControlFlow`. Lowering, CFG construction, transfers and authorization consume the same absolute deadline and limits, preserve finalization reserve and return explicit gaps on exhaustion without restarting the clock. AUTH001 shares that CFG but retains its own must facts and successful-branch contract.

The operation union, exact expression cases and span encoding are defined as frozen records and versioned fixtures in E05-D1 before wiring the lowerer. Transfer/domain work can proceed on handcrafted IR fixtures in parallel; production source integration consumes validated lowering. Tests cover branch ordering, loops, unreachable blocks, unsupported exception constructs, Unicode spans, shadowing, clean/cache equivalence and altered producer identity. Existing PYSEC001/AUTH001/SECRET001–003 limits and advisory claims remain unchanged. Expansion/admission still requires the usefulness and quality evidence; local construction does not advertise these capabilities.

## E03 and E07: transport and artifact boundaries

E03 construction uses strict byte serialization with an injected transport and inert fixtures. Context identity includes report/contract/policy, allowed selection, redaction and truncation state. Retry budgets count every serialized request and response, elapsed time and aggregate bytes across attempts. At most one retry is permitted within the child's existing caps; exhausted/unknown costs refuse further attempts. Actual provider transport needs an operator-approved origin/model/version, actual-address egress enforcement, no proxy/redirect credentials and explicit source-transfer consent. No live provider is selected by this plan.

E07 metadata/provenance/install cards must produce a build/runtime/license ledger before admitting any new dependency. A stdlib verifier must compare actual artifact bytes with the manifest, source revision, exact allowed repository/workflow/run origin and pinned build inputs; a self-asserted manifest is insufficient. `release/build.py` must become a real builder/manifest entry point rather than an import-only re-export. Choose and record exact build-backend versions/digests and redistribution terms in the ledger; unknown measurement/version fields stay unknown and prevent artifact admission, not the local verifier work. Rebuild twice from clean isolated inputs, compare bytes or explain reproducibility limits, and verify installed behavior without source-tree imports. First-release install/removal is testable without inventing a prior accepted release; update/rollback acceptance requires the separately identified prior accepted artifact.

## E08–E11: local interfaces before remote activation

Local client construction is stdio MCP protocol `2024-11-05`, strict schema 1 reports and immutable session-owned handles. The editor extension uses owned plain JavaScript/CommonJS and an explicitly configured admitted CLI executable; set the extension manifest main to `./extension.js` for that implementation; do not add a transpiler merely to run commands. Respect each child matrix, workspace/source consent, byte/session caps and escaped rendering. A local client fixture is not a real client compatibility claim. Remote MCP protocol `2025-06-18` remains gated on E10/E11 remote essentials and the actual service profile.

E09 pure connector construction consumes injected recorded platform responses and emits bounded request descriptors without sending them. E09-D1 first fixes exact request/response descriptor schemas, API/profile, identity fields and iteration/diff coordinates for recorded fixtures and local connector construction. Pin actual platform/version and approved destinations in the connector ledger before live requests. Live permission/isolation/fork/revocation pilots require a disposable authorized project and credentials; local validation has no ambient credentials. Other repository types remain out of scope.

E10 uses `/v1` JSON and a thin owned Python SDK. Start with pure request handlers and injected repository/auth/storage interfaces; a loopback-only test harness has deny-by-default authority and no remote source acquisition. Caller URLs/paths cannot become server acquisition instructions. Use one service process, tenant-keyed stdlib SQLite metadata, operator-owned private report storage and transactional compare-and-set job transitions for the first construction profile. Keep storage keys opaque and tenant-scoped, write reports atomically before completed transition, and preserve coverage independently of job state. An idempotency identity covers tenant/subject/grants-revision/repository/revisions/policy/scope/reviewer and retains job ownership for cancel-own authorization, not just a caller key.

E11 consumes the shared E10 `Principal`/resource/action records and constructs immutable grants plus a deny-by-default evaluator. Authentication is an injected verified-assertion boundary: synthetic assertion fixtures exercise denial but cannot establish SSO acceptance. Do not handwrite cryptography. Actual OIDC/provisioning, issuer/audience/keys, TLS, encryption/key owner and tenant retention defaults require operator choices plus reviewed component/license inventories before activation. No provider, domain or hosted location is guessed. Local policy/audit/deletion construction uses inert key/storage/clock interfaces with durable tombstones and current grants checks on every API/admin/report/cache operation, with an immediate recheck before privileged writes; no source or secret value goes into audit data.

Local order is E10 shared contracts/jobs → E11 grants/policy essentials → E10 app/deployment pilots → E08 remote parity and E11 operations. Whole-package acceptance is not used as a cyclic prerequisite for defining local interfaces. Actual remote activation needs accepted E10-A1/A2 and independently accepted E11-A1/A2, accepted consumed engine/artifacts/publication contracts, explicit source-transfer authority and enforced isolation. E08-A4 remote parity consumes the accepted E10-A4 CLI/API/SDK evidence for the same declared service profile. Seven-day operations, recovery and real client/provider/platform matrices remain separate verification tasks with honest `not_run` records until performed.

## E06: offline patch construction and isolation evaluation

Patch/preference validation and pure RunnerPlan construction do not launch reviewed code. Actual synthetic runner boundary evaluation requires a separately reviewed disposable environment with denied credentials/egress and pinned accepted image/runtime inventory; there is no host fallback. Only independent E06-A2 acceptance can admit reviewed-target execution. Keep the five stages distinct: P0 exact-head/blob/mode/allowed-path preconditions, P1 exact application, P2 parsing, P3 static re-analysis of obligations and P4 actual isolated test receipts. A stale head yields P0=stale and P1=not_run. Proposal provenance remains separate metadata. P2/P3 static construction does not require launching a runner; a skipped/failed P4 cannot become execution evidence. Patching, remote publication, release and deployment remain distinct assigned operations.
