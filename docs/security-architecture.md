# Security and architecture contract

Date: 2026-10-03. Status: proposed revision after independent researcher and reviewer assessment. These are controls for a planned product, not fixes to demonstrated implementation vulnerabilities.

## Purpose and threat boundary

PullRaptor should remain useful when a change contains hostile instructions, misleading metadata, malformed source, or expensive inputs. We can enforce those boundaries with small records and process controls. We cannot promise protection against arbitrary interpreter/Git vulnerabilities or a compromised host simply because the kernel does not intentionally execute source.

The first release supports trusted local operation on an operator-selected repository. Untrusted CI requires a disposable isolated job with no publisher/provider credentials, no secret mounts, bounded filesystem access and denied egress during analysis. Arbitrary supplied `.git` directories, shared privileged runners and externally restored caches are not admitted by that profile. Trusted checkout preparation happens separately. A local subprocess retains its user's filesystem authority unless an OS boundary restricts it; environment filtering and interpreter flags do not change that fact.

## One trusted request, separate receipts

The coordinator creates an immutable `ReviewContract` from pinned inputs and trusted policy before accepting worker results. It contains base tip, comparison base, head, policy and semantic configuration digests, trusted reviewer/extractor identities, profile, declared source classification, and expected `(side, path, capability)` entries with selection reasons. It records excluded/unclassified inventory separately. Operational cache location and hit counters do not enter semantic identities.

E01 scope selection is deterministic: generic inventory covers the union of both manifests; generic text review covers changed admitted text blobs; structural review requires changed known source files on both present sides and the transitive closure of their supported in-repository static imports. Imports are discovered only by current parser facts and classified as repository-resolved, pinned modeled-external or unresolved. Repository candidates/shadowing are checked before external inference; ambiguous candidates remain unknown. Exact-runtime stdlib top-level names establish only module classification, not availability, symbol semantics or successful runtime imports. E01 additionally pins a narrow symbol model for `subprocess.run/Popen/call/check_call/check_output`; unsupported attributes remain unknown for any rule depending on them. Do not parse or execute external modules. An unresolved import produces a required unresolved-context entry; a required dependency that fails parsing is partial. An unrelated malformed file is not required solely because it exists. Other changed source languages remain explicit unsupported structural entries. Exact candidate roots and import-model limitations are recorded; this does not claim full runtime import equivalence.

Scope keys have a discriminant: file entries use snapshot/path-bytes/capability; import-lookup entries use snapshot/source-occurrence/canonical module target/relative level/capability. Missing `x` and `y` from one source file are distinct entries, not invented manifest paths. Repeated equivalent lookups may share a key with all source witnesses retained.

Scope expansion during discovery is coordinator-owned, append-only and sealed before policy evaluation. Coordinator discovery completion is a separate required predicate: exhausted discovery cannot become complete just because all currently known receipts completed. Workers may propose dependencies, but cannot remove expected entries or declare their own smaller requested scope. Unexpected inputs require a new scope revision, not a self-authorized receipt.

`validate_receipts(contract, receipts)` rejects missing, duplicate, foreign, wrong-revision and wrong-capability entries. Receipt validity is separate from whether the capability completed. A worker's `complete` field has no authority by itself. Every incomplete entry carries a stable cause, affected capability, and a trusted next action such as preparing missing objects, choosing a supported runtime, increasing a declared bound, or explicitly selecting the narrower diff profile. Suggested actions are data; attacker-supplied commands and URLs are never executed.

An observation can remain supported when all its own prerequisites completed, even if another file is partial. The overall review still returns incomplete. Negative whole-scope claims and enforcement require the complete applicable domain. Missing baseline analysis makes introduction/repair assertions unknown without discarding a sound head observation.

## Small process boundary

One process helper owns absolute deadlines, bounded pipes, launch environment and termination for both Git and parser workers. No operation can reset the overall deadline. Metadata, text hunks, parsing and rendering all consume the same review budget; oversized non-source text is bounded too. Record invocation start once. Ref/policy bootstrap has a one-second work cutoff and a three-second final cutoff, matching the minimum admitted duration and two-second reserve. If preparation fails to finish, emit the fixed failure variant under those initial controls without waiting for policy. After validation, compute effective cutoffs from the original start and trusted duration, never from the current time. This prevents slow preparation from retroactively exceeding a newly discovered shorter budget. Reserve the final two seconds of the default 60-second budget and 16,384 output bytes for the fixed failure envelope. Normal analysis/full serialization uses the earlier work cutoff; failure finalization alone can use the reserve. Reject duration below three seconds or report byte/item/depth/string limits below envelope minima. Coordinator returns the report plus its effective operational deadline/record limits to the renderer; those values do not enter canonical identities.

| Boundary | Required control | Unsupported condition |
|---|---|---|
| Executable/startup | Trusted absolute paths; parser `-I -S`; neutral working directory; no inherited startup paths | Tool capability failure is explicit; no fallback to an untrusted executable |
| Environment/handles | Minimal allowlist, closed inherited descriptors, no source/provider/publisher credentials | Host filesystem isolation is a separate deployment requirement |
| Git | Option-safe refs, literal paths, disabled replacement refs/lazy fetch/optional writes/external helpers; trusted metadata admission | Missing local objects or unsupported required flags return partial/unavailable |
| Output/time | Stream stdout/stderr within caps; kill and reap process tree on timeout/overflow | A killed process never supplies a completed receipt |
| OS resources | Record OS and actual deadline/process-tree/CPU/memory/output enforcement | Hostile profile refuses unsupported isolation; local mode exposes gaps |

Record the exact Git executable version and probe required behavior in a neutral directory. Use `rev-parse --verify --end-of-options <ref>^{commit}`; reject invalid ref inputs and subsequently use only validated OIDs. Apply `--no-lazy-fetch`, `--no-replace-objects` and literal path handling to every relevant invocation, not merely a fetch wrapper. Do not widen `safe.directory` globally.

Do not let attributes, environment configuration or external tools define coverage. Authoritative inventory comes from tree/blob metadata. Obtain admitted textual hunks from isolated per-blob comparisons with trusted fixed paths/options, so `.gitattributes` cannot hide requested code. Record diff exit 1 as a normal difference, not a tool failure. Large/binary blobs remain metadata-visible and text coverage is partial when requested bytes cannot be admitted.

## Bounded record ingestion and rendering

Use one stdlib JSON decoder at every external-data boundary. Before decoding, cap bytes and nesting using a string-aware delimiter pass; reject duplicate object keys, nonfinite numbers, malformed UTF-8/unpaired surrogates, unknown fields, invalid ranges, and booleans where integers are required. After decoding, bound collection counts and strings. Enforce output pipe caps before buffering a full response. The configured encoder's `allow_nan=False` alone is insufficient for decoding.

Initial proposed limits: depth 64; 100,000 aggregate collection items per worker/cache message and 1,000,000 per report; 4,194,304 UTF-8 bytes per decoded string; 8,388,608 bytes per worker message, cache entry or report; 65,536 bytes of stderr per process; 8,388,608 bytes of aggregate textual diff output per review. Count every object member and array element recursively, once each; bound all decoded strings/keys. Worker source uses base64 so the admitted 2-MiB blob fits without JSON escape inflation. Report allowance accommodates ordinary 10,000-entry manifests without promising every legal input fits. Per-protocol tighter limits may apply. Any necessary scope omitted by these bounds is partial, never silently removed. Invalid cache is a miss; failed worker data is partial; invalid publication input is rejected. Error details are bounded and redacted.

Report schema 1 is a tagged union. `kind=full` contains the complete report structure (which can truthfully describe partial analysis). `kind=limit_failure` contains only schema/kind, known pinned input identities (null when not established), exit code 2, fixed cause/limit fields, explicit `analysis_complete=false`, `details_omitted=true`, and a fixed list of omitted domains with counts when known. It has no finding, support, publication-eligibility or negative-scope claims. Limit failure is schema-valid, at most 16,384 bytes and 128 collection items, and never eligible for inline publication. Report configuration must allow at least those bytes/items, depth 8 and 256 UTF-8 bytes per string, including format wrappers. Markdown explains the omissions; JSON uses the variant directly; SARIF places it in run properties with incomplete execution and a diagnostic, never interprets empty results as clean. Byte/item/deadline exhaustion uses this variant, including when expected scope itself cannot fit. Ordinary required-work failure can still use a full partial report when it fits.

Terminal output visibly escapes controls, carriage returns and directional characters. Markdown escapes literal source/filename/claim text and prevents code-fence or link breakout. Do not emit untrusted raw HTML, active URLs, Mermaid syntax or terminal control sequences. One owned link builder uses a fixed trusted origin, pinned commit and individually percent-encoded validated path segments; query/fragment/reserved characters cannot alter authority or file identity. Escape display labels independently. Before E03/E04 diagrams are enabled, an owned serializer must generate opaque node identifiers and escaped bounded labels from validated records; no model/source text supplies graph syntax. JSON preserves bounded data using correct escaping; UI trust does not come from valid JSON. SARIF message properties cannot grant URL, command or fix authority.

## Cache trust and content binding

Cache only `ContentFacts`: occurrence-free syntactic facts derived from a blob, exact runtime, schema and all extractor components. `BoundFacts` adds current path/side/snapshot through trusted coordinator binding. Resolution and dependency results remain run-local and never enter a parser cache. Validate source bounds and current blob identity when binding.

Only operator-owned private cache storage outside reviewed trees is admissible. Reject symlink/reparse redirects, foreign ownership, unsafe shared writes and externally supplied entries. On POSIX, require private directory/file permissions and descriptor-relative no-follow access where available; other platforms need equivalent verified controls or cache stays off. Atomic replacement handles crashes, not authenticity.

CI defaults to no cache. An untrusted or shared cache is ignored even if its schema, key and self-reported checksum are valid. Re-extraction is the smallest safe alternative; signatures and key management are deferred. A fresh check of emitted positives cannot detect omitted facts. Private-cache reuse assumes its host/writer is trusted; hostile same-user compromise is outside that assumption. Cache admission/failure information belongs in execution metadata, while any consequent unfinished requested analysis remains in coverage.

## Proposals cannot grant authority

AI and imported tools return distinct `Proposal` records with hypotheses, proposed locations and producer/context provenance. Their schema has no fields for support states, permissions, executable configuration, provider destinations or publication eligibility. Trusted validators alone create `Evidence` or `Finding` records, and only for the exact predicate they checked. A real line reference establishes a valid reference, not the proposed defect.

Model instructions, issue text, source comments and external reports cannot increase budgets, choose destinations, execute tools, weaken policy or publish a patch. AI receives source as labeled data and has no autonomous execution capability. Local and remote providers are separate explicit profiles. Remote transport uses operator-approved HTTPS origin/path, authenticated TLS, no automatic redirects or ambient proxies, and credentials only for the approved origin. Validate actual resolved/connected addresses or enforce an OS egress allowlist; a hostname precheck alone does not prevent DNS rebinding. Private/loopback/link-local destinations require the explicit local-provider profile. E03 must select and test the exact transport before activation.

## Publication and lifecycle

Bind publication to platform-derived repository/PR/workflow/run identity, artifact origin, reviewed head, base tip, comparison base, policy digest, reviewer artifact and requested-scope manifest. Same head in another PR is not the same authorization context. If base policy/scope advances while head stays unchanged, require a new analysis. Recheck before posting, attach exact revision identities, and mark later drift as outdated; this is not a transactionally current merge approval.

Keep a stable repository/PR/rule/obligation key separate from each revision-bound observation ID. Detection delta against the merge base is not publication lifecycle: the same branch finding can remain newly detected on every push. Reconcile the bot's own platform records after duplicate events or ambiguous POST outcomes. Distinguish dismissal, published state, current observation and substantive evidence. Changed witnesses merit renewed review; an unchanged dismissed observation does not silently become resolved or correct. Ambiguous matching stays visible.

E02 ships one hardened CI template: full action commit pins, explicit minimal permissions, no persisted checkout credentials, trusted reviewer installation outside head content, input strings passed as data, and no publisher restore of analysis-controlled caches or checkout of head code. Dedicated disposable jobs are the default; persistent privileged runner support is a separate deployment decision. Publication remains COMMENT-only unless a later explicitly reviewed policy adds another action.

## What remains small

E01 adds a request record, content/occurrence type split, bounded codec, shared process helper and safe renderer tests. These do not require a graph service, cryptographic identity system, web framework or third-party kernel package. E02–E06 enforce the same boundaries through their own child plans. Resource and code budgets still apply; add measurable usefulness through a small real-review pilot before expanding language/security breadth.
