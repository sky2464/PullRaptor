## 1. Scope & Objective

Milestone E03 introduces an **optional, provider-neutral AI explanation and context adapter** for PullRaptor.
The core deterministic review engine remains strictly offline with zero external network access and zero third-party runtime package dependencies.

AI capabilities are strictly **opt-in** and produce **typed, untrusted proposals**:
1. **Finding Explanations & Challenge Analysis:** Plain-text explanation of deterministic findings (rules, obligations, witnesses), identifying why an obligation exists and providing advice on how to resolve or refute it.
2. **Context Enrichment:** Safe ingestion of external context (pinned issue descriptions and bounded CI failure log snippets) with strict size limits, sanitization, and redaction.
3. **Test / Doc Suggestions:** Generating unit test sketches or docstring improvements for changed functions without executing code or claiming automated merge authorization.

---

## 2. Security Boundaries & Invariants

Following the [Security Architecture Contract](../../security-architecture.md) and Section 9/10 of the Master Plan:
1. **Zero External Runtime Dependencies:** AI transport uses standard library `urllib.request` exclusively. No vendor SDKs, heavy HTTP libraries, or third-party packages.
2. **Zero Default Egress:** If no model configuration or API endpoint/key is provided, egress is exactly zero.
3. **Strict Resource Bounds:**
   - Maximum requests per review invocation: 2.
   - Aggregate context bytes transmitted: $\le 65,536$ bytes.
   - Maximum tokens requested per response: $2,048$ tokens.
   - Maximum cumulative network duration: $60.0$ seconds.
4. **Prompt Injection Resistance:**
   - All external context (diffs, issue text, CI logs, commit messages) is treated as untrusted text.
   - Prompts enforce strict role-delimited envelopes with control-character stripping and delimiter escaping.
   - External inputs cannot alter system instructions or authorize merge/verdict changes.
5. **Redaction of Sensitive Values:**
   - Scan outbound context for common secret tokens (e.g. `ghp_`, `bearer `, API keys, private key headers) and replace with `[REDACTED]`.
6. **Untrusted Proposal Classification:**
   - AI outputs are classified as `UntrustedProposal`.
   - AI outputs NEVER alter deterministic `Finding.policy_class`, NEVER silence findings, and NEVER convert an advisory finding into a blocking finding or vice versa.
   - Explanations render with explicit disclaimer markers in Markdown and JSON.

## 3. Data Models & Interface Contracts

```python
@dataclass(frozen=True)
class AIConfig:
    enabled: bool = False
    endpoint: str = ""                # Pinned HTTPS endpoint
    api_key: str = ""                 # Secret token / Bearer token
    model: str = "default"            # Model identifier
    max_requests: int = 2
    max_context_bytes: int = 65_536
    max_output_tokens: int = 2048
    timeout_seconds: float = 30.0

@dataclass(frozen=True)
class ExternalContext:
    issue_text: str = ""
    ci_log_snippet: str = ""
    commit_message: str = ""

@dataclass(frozen=True)
class AIProposal:
    kind: str                         # "explanation" | "suggestion"
    target_rule: str | None           # e.g. "PY001"
    target_span: str | None           # e.g. "src/app.py:10"
    content: str                      # Sanitized proposed markdown text
    model: str
    tokens_used: int = 0
```

## 4. Verification and Acceptance

- Unit tests verifying:
  1. Default disabled state has zero network calls.
  2. Strict context byte ceiling ($65,536$ bytes) truncates cleanly without errors.
  3. Sensitive token redaction (`ghp_...`, Bearer tokens).
  4. Prompt injection resistance (injected `Ignore previous instructions` retained as inert quoted data).
  5. Deterministic report equivalence: AI suggestions are additive only and do not alter canonical findings.
